# Agent skills (repo `agent-skills`)

Skills that teach any coding agent to read and write Synod. Claude Code
is the primary target; the same content is exposed for other agents.

## Layout

```
skills/synod/SKILL.md            the entry point (Claude Code skill format)
skills/synod/reference/
    grammar.md                   spec/02 condensed: structure + language words
    phrases.md                   pattern rules, resolution, results, blocks
    contexts.md                  the four contexts table and what each may do
    canonical.md                 spec/10 table
    std-catalog.md               GENERATED by `synod doc --catalog`
    trace-events.md              spec/08 table
    errors.md                    spec/11 codes with one-line fixes
    examples/                    copies of dsl/examples, canonical
AGENTS.md                        the same entry point for other agents
.github/workflows/sync.yml       fails when std-catalog.md or examples are stale
```

## SKILL.md (outline)

```markdown
---
name: synod
description: Read, write, check and run Synod (.synod) programs that model
  distributed systems, system designs and database internals for animation.
  Use whenever a task mentions Synod, .synod files, synod.mod, or asks to
  "animate" or "simulate" a protocol in a Synod workspace.
---

# Writing Synod

1. Look before writing: `synod doc` for std, search the workspace and
   examples for an existing package. Prefer writing only a main file
   (`define main`).
2. Every argument is one item: parenthesize every nested phrase and every
   multi-item condition. `if (n.Role is "leader")`, `set n.x to (n.x plus 1)`.
3. Qualify every imported name (`net.Send`, `gossip.Join`,
   `n.gossip.Known`); never qualify your own package's names (`n.Known`,
   `Quorum`).
4. Node code names its node with a receiver: `define [n: Node] Version`,
   `when [n: Node] (net.Received …)`, `define [n: Node] start`. It touches
   only `n`'s state and talks to other nodes with `net.Send m from n to p`.
   `deliver` and faults live in `define main`.
5. Types are explicit: `[ns: list of Node]`, `[m: map of node to number]`.
   A `node` has no fields; `Node` or `pkg.Node` does.
6. Looks are optional: `std/look/basic` animates everything by default.
7. Run `synod fmt`, then `synod check` until clean, then `synod run` and
   confirm the trace shows what was asked. Never hand back unchecked code.

Reference files: grammar.md, phrases.md, contexts.md, canonical.md,
std-catalog.md, trace-events.md, errors.md, examples/.
```

## Sync rules

- Each `dsl` release tags a matching `agent-skills` release.
- CI regenerates `std-catalog.md` with the current `synod` and copies the
  examples; any diff fails the build.
- Every example in the skill must pass `synod check`.
